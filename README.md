# serial_imu_bridge

A ROS 2 package that reads framed IMU data from a microcontroller over UART and publishes it as `sensor_msgs/Imu`, plus a complementary filter node that estimates roll and pitch. The repo also contains the STM32 firmware that produces the frames.

The framing, CRC, IMU decoding and filter math are kept free of ROS code, so they are unit tested with plain pytest and mirrored in the C firmware.

## Architecture

```
MPU-6050 --I2C--> STM32L432KC firmware --UART 115200, CRC-16 frames--> bridge_node --/imu/data_raw--> imu_filter --/imu/data-->
                                                                         \--/diagnostics (link health)
```

## Serial protocol

| Field | Size | Notes |
|---|---|---|
| Sync | 2 bytes | `0xAA 0x55` |
| Length | 1 byte | Payload length, at most 64 |
| Sequence | 1 byte | Increments per frame, wraps at 255; gaps are counted as lost frames |
| Payload | `Length` bytes | IMU: six little-endian `int16` (ax, ay, az, gx, gy, gz), MPU-6050 at ±2 g and ±250 °/s |
| CRC | 2 bytes, big endian | CRC-16/CCITT-FALSE (poly `0x1021`, init `0xFFFF`) over Length, Sequence and Payload |

After a bad CRC or garbage, the parser skips to the next sync word and keeps counting what it saw.

## Nodes and topics

**`imu_bridge`** (`bridge_node`)

| Topic | Type | Content |
|---|---|---|
| `imu/data_raw` | `sensor_msgs/Imu` | Acceleration (m/s²) and angular velocity (rad/s). No orientation (`orientation_covariance[0] = -1`). Sensor-data QoS (best effort) |
| `/diagnostics` | `diagnostic_msgs/DiagnosticArray` | `frames_ok`, `crc_errors`, `lost_frames`, `resyncs`, `connected`, `frame_rate_hz`. WARN on new errors, ERROR when no valid frame arrived or the port is not open |

Parameters: `port` (empty = simulated source), `baud`, `frame_id`, `poll_hz`, `sample_rate_hz`, `sim_rate_hz`, `sim_error_rate`. Frames that arrive in one read get timestamps spread back by the sample period. On a serial error the node logs, closes the port and retries once per second.

**`imu_filter`** (`imu_filter_node`)

Subscribes to `imu/data_raw` and publishes `imu/data` with the orientation quaternion. Complementary filter: gyro integration blended with the accelerometer tilt (`alpha`), accelerometer ignored when |a| is far from g (`accel_gate`), samples with dt ≤ 0 rejected, gaps longer than `max_dt` re-initialise from the accelerometer. Yaw is held at 0: it is not observable without a magnetometer.

## Firmware

`firmware/` targets an STM32 Nucleo-L432KC with an MPU-6050 on I2C1 and USART2 at 115200 baud, about 100 Hz.

- `protocol/`: portable C99 CRC-16, frame encoder and payload packing
- `drivers/`: MPU-6050 driver written against an I2C callback interface, so it is tested on a PC with a fake bus
- `app/main.c`: STM32 HAL application skeleton (CubeMX init code to generate in STM32CubeIDE)
- `tests/`: host tests and the C → Python golden check
- `sim/virtual_board.c`: a virtual board for software-in-the-loop. It links the real `drivers/mpu6050.c` and `protocol/frame.c` against a simulated MPU-6050 register model (power-on sleep, WHO_AM_I, big-endian data registers, small noise) and writes frames to a serial device

### Software-in-the-loop without hardware

```
virtual_board (real driver + frame code, simulated MPU-6050) --> socat pty pair --> bridge_node (real serial port) --> imu_filter --> sil_check.py
```

```bash
docker run --rm -v "$PWD/tools:/tools:ro" serial_imu_bridge bash /tools/sil_test.sh
```

The board holds a fixed roll and pitch, so `sil_check.py` checks the rate, the filter angles and the CRC error count. The script then unplugs the virtual cable for 4 s and plugs it back to check that the node reports the lost port and reconnects.

## Run

```bash
python -m pytest test -v                 # ROS-free tests
python tools/benchmark_parser.py         # parser throughput on this PC
```

Firmware host tests (Windows, with GCC on the PATH):

```powershell
powershell -File firmware\build_tests.ps1 -Gcc <path to gcc.exe> -Python <path to python.exe>
```

With Docker (ROS 2 Jazzy image):

```bash
docker build -t serial_imu_bridge .
docker run --rm -it serial_imu_bridge                                                  # launch the bridge
docker run --rm -v "$PWD/tools:/tools:ro" serial_imu_bridge bash /tools/ros2_smoke_test.sh  # smoke test
```

## Benchmark

`tools/benchmark_parser.py` measured tens of thousands of frames/s for the Python parser on the development PC; the runs were noisy and are all recorded in `tools/benchmark_results.txt`. A 115200-baud link carries at most about 640 of these 18-byte frames per second, so the parser is not the bottleneck. This measures the parser only, not a robot.

## Known limitations

- **Sequence gaps:** lost frames are computed modulo 256, so a duplicated frame counts as 255 lost, an MCU reset counts as a large loss, and a gap of exactly 256 frames counts as none. Only a host-side reconnect (`reset_link`) is handled.
- **Corrupted length byte:** a corrupted length can hold the next valid frames until enough bytes arrive; they are then recovered, about one read later.
- **Filter weighting:** `alpha` is applied per sample, not per second, so bunched samples over-weight the accelerometer. A time constant with alpha derived from dt would fix it.
- **Firmware:** the MPU-6050 low-pass filter and sample-rate registers are not configured, sampling follows the system tick instead of the sensor's data-ready signal, and there is no I2C bus recovery.
- **No calibration:** no gyro bias estimate, accelerometer and gyro covariances left at zero, filter tilt standard deviation is a placeholder.
